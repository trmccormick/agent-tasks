# Hyku/Hyrax Repo Relationship

**Key insight:** The wvu_knapsack project's architecture spans THREE repos, not two:

| Local Path | Remote | Purpose |
|---|---|---|
| `/Users/tam0013/Documents/git/wvu_knapsack/` | wvulibraries_knapsack | WVU customizations/overrides (the deployed app) |
| `wvu_knapsack/hyrax-webapp/` | samvera/hyku (git submodule) | **Hyku** — multi-tenant layer on top of Hyrax |
| `/Users/tam0013/Documents/git/hyrax/` | samvera/hyrax | Core Hyrax framework (not a submodule of hyku locally — separate local clone) |

## Architecture Stack (Bottom → Top)

```
Hyrax (/Users/tam0013/Documents/git/hyrax/)  ← base framework
    ↑ (Hyku builds on top)
Hyku (/Users/tam0013/Documents/git/hyku + wvu_knapsack/hyrax-webapp submodule)  ← multi-tenant layer
    ↑ (wvu_knapsack customizes Hyku)
WVU Knapsack (/Users/tam0013/Documents/git/wvu_knapsack/)  ← WVU's deployment/customizations
```

## Critical Misconception to Avoid

**NEVER refer to hyrax-webapp as "the Hyku repo" in isolation.** It IS the Hyku repo (via submodule), but understanding that Hyku itself is built on top of Hyrax is essential for:
- Debugging upstream issues (is it a Hyku problem or a Hyrax problem?)
- Filing correct upstream PRs (some changes need `samvera/hyku`, others need `samvera/hyrax`)
- Understanding the fix chain (e.g., Hyku #3369 depends on Hyrax #7678)

## Local Development Implications

1. **hyrax-webapp/ is a submodule** — anything modified there gets overwritten on `git submodule update`
2. **/Users/tam0013/Documents/git/hyrax/ exists separately** — not tracked as a submodule in wvu_knapsack, but Hyku pulls its dependency from upstream samvera/hyrax
3. **All customization stays in wvu_knapsack/** — decorators, initializers, config overrides (never edit hyrax-webapp/ or /Users/tam0013/Documents/git/hyrax/)
