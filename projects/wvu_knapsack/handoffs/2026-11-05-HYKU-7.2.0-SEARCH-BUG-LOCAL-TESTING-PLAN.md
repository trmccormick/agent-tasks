## Executive Summary

This document provides a structured testing plan to investigate the Hyku 7.2.0 search bug where:
- Search returns empty results despite records existing in Solr
- Root cause identified as **Valkyrie indexer writes to wrong Solr collection** (code-level issue)
- v7.1.3 also affected (not 7.2.0-specific — data/infra bug persists across versions)

**Goal:** Systematically test, capture diagnostics, and produce findings that inform the fix strategy.

### 1.1 Verify Records Exist in Solr at v7.1.3

**Objective:** Establish that data exists and is queryable at baseline.

```bash

# List all collections (or cores) in Solr
curl -s "http://localhost:8983/solr/admin/cores?wt=json" | python3 -c "import sys, json; [print(c) for c in json.load(sys.stdin)['status'].keys()]" > /tmp/solr-coll-list-713.txt

# Check document counts per collection
for coll in $(cat /tmp/solr-coll-list-713.txt); do
  count=$(curl -s "http://localhost:8983/solr/$coll/select?q=*:*&rows=0&wt=json" | python3 -c "import sys, json; print(json.load(sys.stdin)['response']['numFound'])")
  echo "$coll: $count docs"
done > /tmp/solr-doc-counts-713.txt

cat /tmp/solr-doc-counts-713.txt
```

## Risk Assessment & Mitigation

### Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| Stack Car fails to start on 7.2.0 branch | HIGH | Keep v7.1.3 snapshot ready; revert immediately |
| Gem version conflicts prevent build | HIGH | Use committed Gemfile.lock as fallback |
| Solr data loss during volume recreation | MEDIUM | Save /tmp test data before `docker compose down --volumes` |
| Testing modifies production tenant state | LOW | Stack Car is disposable; can restart fresh |
| Testing takes longer than 2 hours | MEDIUM | Focus on critical path: Phase 2.3 (same queries as 1.x) |

### Safety Measures

1. **Snapshot before testing**: Take clean snapshot in hykudev (already done per status.md)
2. **Save /tmp data immediately**: Don't rely on persistence across docker restarts
3. **Keep v7.1.3 accessible**: Can `git checkout main` and revert instantly
4. **Document every step**: Every command logged to /tmp files for audit trail
5. **No changes to source code**: This is pure testing — only read queries, never write fixes
