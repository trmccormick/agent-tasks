## Design Decisions Confirmed by Tracy

### 1. Escalation Priority Order (Cheapest Path First)
1. **Atmospheric gases** → trivial intake machine (no ISRU gate)
2. **Regolith harvesting** → simple scooping (harvester, no mine infrastructure)
3. **Mining + ISRU processing** → water ice in PSRs requires mine setup + PVE
4. **Imports** → only when body genuinely cannot produce

### 2. Material Classification by Harvesting Tier

| Tier | Materials | Processing Required |
|------|-----------|---------------------|
| Trivial (atmospheric) | CO₂, N₂, O₂ if present in atmosphere | Simple gas separator/intake — no ISRU |
| Requires ISRU gate | O2 from regolith/water ice, metals from smelting | PVE/TEU deployed |
| Requires mining + ISRU | Water ice in PSRs | Mining site setup + specialized extraction + PVE |

### 3. CO₂ on Mars is Trivially Harvestable
- 95% of atmosphere — simple intake machine connected to gas separator
- Used for MOXIE-style O₂ production, Sabatier methane synthesis (CO₂ + H₂ → CH₄ + H₂O), greenhouse pressurization
- **Fundamentally different from O2** which requires PVE splitting

### 4. Processing Gate Applies Only Where Needed
- CO₂ on Mars: no processing check needed (atmospheric gas)
- N₂ on any atmosphere body: no processing check needed (atmospheric gas)
- O2 from regolith/water ice: requires PVE/TEU deployed
- Metals from smelting: requires PVE/TEU deployed

### 5. AI Manager Cannot Bootstrap Without Local Extraction
- The AI Manager won't create a settlement on Luna/Mars if it can't extract materials for human habitation
- It must find local sources first — everything cannot be imported
- This is the fundamental constraint that `can_harvest_locally?` serves

### 6. Human Check Gates Life Support Priority, Not Harvesting
- The `humans_present?` check determines if life support resources (O2, water, food) get priority in escalation order
- It does NOT gate whether harvesting happens — automated harvesters work regardless of human presence
- Humans become required when committing to an import pipeline that needs management

### 7. Parts Escalation Chain
When a critical part is needed and no backup exists:
1. **Local manufacture** → check blueprints + available facilities (fabrication_plant, foundry, refinery)
2. **Partial import + local assembly** → import only components that can't be made locally
3. **Emergency special missions** → route to player-completed missions for rewards (not AI Manager)
4. **Urgent resupply from AstroLift** → last resort, batch as much as possible into one shipment

### 8. Emergency Resupply Batches All Pending Needs
- The AI Manager maintains a **running manifest of pending needs** (ongoing + emergency)
- When an emergency triggers, it batches all current pending items into one urgent shipment
- This is why manifests should be auto-generated by the AI Manager — dynamic lists that grow as needs accumulate

### 9. Two Distinct Harvesting Tiers
- **Atmospheric gases** (trivial intake machine): CO₂, N₂, O₂ if present in atmosphere
- **Geosphere/hydrosphere** (requires mining equipment): water ice in PSRs needs mining site setup + specialized extraction + PVE processing
- Regolith is "scooping" not "mining" — harvester scoops regolith and dumps it into TEU/PVE. No mine infrastructure needed.

### 10. Escalation Covers Two Categories
- **Stockpile levels** → "do we have enough O2/water?"
- **Equipment health/spare parts inventory** → "if the PVE dies right now, can we keep producing O2?"

## Critical Gaps Identified

### Gap 1: `can_harvest_locally?` Missing CO₂ Atmospheric Case
**Current code**: Falls through to `else` bucket and checks regolith/geosphere for CO₂  
**Problem**: Mars has ~95% CO₂ in atmosphere — should be trivially harvestable via intake machine  
**Fix needed**: Add `when 'CO2'` case parallel to N2:
```ruby
when 'CO2'
  celestial_body.atmosphere&.gases&.any? { |g| g.name == 'CO2' }
```

### Gap 2: No ISRU Capability Gate for O2 from Regolith/Water Ice
**Current code**: Grants direct O2 credit purely from atmosphere gas presence  
**Problem**: On bodies without atmospheric O2 (Luna, Mars), O2 must come from regolith/water ice via PVE/TEU — but no check for whether the settlement has processing units deployed  
**Fix needed**: Add ISRU capability gate when sourcing O2 from regolith/water ice on bodies without atmospheric O2

### Gap 3: Hardcoded World Names in `supplied_via_hlt_mission?`
**Current code**: Uses `case celestial_body.name.downcase` with hardcoded lists for 'luna' and 'mars'  
**Problem**: Violates data-driven design — breaks on procedurally generated bodies, stays static even if body properties change (e.g., terraformed Mars)  
**Fix needed**: Query the body's **current** attributes (`celestial_body.atmosphere.gases`, `celestial_body.hydrosphere`, `celestial_body.materials`) dynamically. Any import route logic should query actual game state (is there an operational skimmer route from a colonized body that has this material?) rather than a pre-written manifest.

### Gap 4: No Proactive Needs Assessment
**Current code**: `EscalationService.determine_escalation_strategy` is **reactive** — triggered by an order that already exists  
**Problem**: The AI Manager can't proactively identify what it needs. It only reacts when something triggers an order.  
**Gap**: No periodic assessment that checks:
- Stockpile levels vs consumption rates (O2, water, food, metals)
- Equipment health/spare parts inventory (TEU, PVE, harvesters)
- Population vs habitat capacity
- Power production vs usage

### Gap 5: "Luna Manifest Generation Service" is Hardcoded to One Body
**Current code**: Pre-written JSON manifests (`lunar_precursor_manifest_v1.json`, `luna_base_establishment_manifest_v2.json`) with hardcoded cargo lists for Luna  
**Problem**: Not data-driven — these are static manifests written once, not dynamically generated by the AI Manager based on actual needs  
**Fix needed**: Generic "Manifest Generation Service" that works for any celestial body, generating manifests based on what the settlement actually needs

## Current Code State

### `can_harvest_locally?` (escalation_service.rb:457-473)
```ruby
def self.can_harvest_locally?(settlement, material)
  celestial_body = settlement.celestial_body
  case normalize_material(material)
  when 'O2'
    celestial_body.atmosphere&.gases&.any? { |g| g.name == 'O2' }
  when 'H2O'
    hydrosphere_has_water = celestial_body.hydrosphere&.total_liquid_mass&.positive?
    geosphere_has_ice = celestial_body.materials.where(location: 'geosphere').where("name ILIKE ?", "%ice%").exists?
    hydrosphere_has_water || geosphere_has_ice
  when 'N2'
    celestial_body.atmosphere&.gases&.any? { |g| g.name == 'N2' }
  else
    # Check regolith composition for other materials
    celestial_body.materials.where(location: 'geosphere', name: material).exists?
  end
end
```

**Issues**:
- Missing CO₂ atmospheric case (falls to else → checks geosphere, wrong)
- O2 has no ISRU gate when body lacks atmospheric O2
- H2O has no mining equipment check for PSR water ice

### `supplied_via_hlt_mission?` (escalation_service.rb:430-445)
```ruby
def self.hlt_mission_manifest(celestial_body)
  case celestial_body.name.downcase
  when 'luna'
    ['O2', 'N2', 'CH4', 'CO2', 'C2H6', 'hydrocarbons', 'CO2', 'N2', 'CH4']
  when 'mars'
    ['N2']
  else
    []
  end
end
```

**Issues**:
- Hardcoded world names (violates data-driven design)
- Stays static even if body properties change
- Duplicates in Luna list (CO2, N2, CH4 appear twice)

### `determine_escalation_strategy` (escalation_service.rb:399-425)
```ruby
def self.determine_escalation_strategy(order)
  material = order.resource
  settlement = order.base_settlement
  celestial_body = settlement.celestial_body

  # ISRU requires human oversight/supervision
  return :scheduled_import unless humans_present?(settlement)

  # Priority 1: ISRU-first — always harvest locally if possible
  return :automated_harvesting if can_harvest_locally?(settlement, material)

  # Priority 1.5: Manufacture locally if possible (e.g., smelt iron from regolith)
  return :deploy_manufacturing_unit if can_manufacture_locally?(settlement, material)

  # Priority 2: Material supplied via active HLT skimmer missions
  return :scheduled_import if supplied_via_hlt_mission?(material, celestial_body)

  # Priority 3: Default to import if not local and not HLT
  :scheduled_import
end
```

**Issues**:
- `humans_present?` gates ALL harvesting — should gate life support priority, not harvesting itself
- No proactive needs assessment before orders are created
- No parts/equipment escalation path

## What Needs to Be Fixed (Priority Order)

### Immediate Fixes (in `can_harvest_locally?`)
1. Add CO₂ as atmospheric case (parallel to N2)
2. Add ISRU capability gate when sourcing O2 from regolith/water ice on bodies without atmospheric O2
3. Keep O2 checking atmosphere for Earth (free source)
4. Stay generic and data-driven — check what the body has + equipment available, not per-world hardcoded logic

### Medium-Term Fixes
5. Remove hardcoded world names from `supplied_via_hlt_mission?` — query actual game state
6. Build proactive needs assessment service (periodic check of stockpiles, equipment health, population vs capacity)
7. Rename "Luna Manifest Generation Service" to generic "Manifest Generation Service" that works for any body

### Long-Term Architecture
8. Add `can_produce_locally?` check (parallel to `can_harvest_locally?`) for parts/equipment escalation
9. Build AI Manager self-assessment system that generates orders before they become critical
10. Ensure manifests are dynamically generated by the AI Manager based on actual needs, not pre-written cargo lists

## Key Design Principle to Remember

**The AI Manager's job is to keep the base running with what's available locally first.** It should always prefer local harvesting/manufacturing over imports. Imports are fallback, not primary. Travel time matters — by the time an import arrives, the settlement might have already run out of O2/water. Local production is always preferred for critical life support resources.

**All escalation logic must be data-driven and work on any celestial body.** No hardcoded world names, no static manifests. Query the body's current attributes dynamically.
