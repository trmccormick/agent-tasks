- Hyku 7.2.0 breaks search (empty results despite records in Solr)
- Root cause identified: Valkyrie indexer writes to wrong Solr collection; search queries different collection
- Gemfile.lock already fixed (startup crash)
- hykudev v7.1.3 baseline stable with snapshot taken

- Stack Car is safe (can restart freely, no production risk)
- Jr dev confirmed local setup works at base version

- Research: What tests should be run?
- Document: How should they be compared?
- Plan: What diagnostic data matters?
- Procedure: Exact commands for each phase

## Planning Priorities (In Order)

### Priority 1: Define Testing Phases (HIGH)
**What:** Create a structured approach to test v7.1.3 (working) vs v7.2.0 (broken)

**Required sections:**
- Phase 1: Environment setup — What state should Stack Car be in?
- Phase 2: v7.1.3 baseline testing — What proves it works?
- Phase 3: v7.2.0 broken testing — Same tests, showing difference
- Phase 4: Comparative analysis — How to isolate the code change?

**Output:** Clear, step-by-step procedures for each phase

### Priority 2: Diagnostic Data Collection (HIGH)
**What:** Define what data will be collected at each phase to understand the bug

**Required sections:**
- Which logs to capture? (Rails, Solr, Docker)
- Which Solr queries to run? (collection list, doc counts, index structure)
- How to check which collection Rails thinks it's using?
- Code comparison procedures (git diff between versions)
- How to document findings for hand-off

**Output:** Diagnostic checklist with specific commands

### Priority 3: Risk & Sequencing (MEDIUM)
**What:** Address what could go wrong and how to proceed

**Required sections:**
- Potential failure points
- Rollback/revert procedures
- Should we take snapshots? When?
- After local testing, what's next?
- Timeline estimate with contingencies
- Parallel/blocking dependencies

**Output:** Risk assessment and mitigation strategy
